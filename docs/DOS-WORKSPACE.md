# DOS / TUI workspace

Choose **Tools > Options > General > Workspace mode > DOS / TUI**, or **View > DOS / TUI Workspace**. **Tools > DOS Workspace Options** configures the palette and cell metrics independently. Classic remains the default. Options are staged until OK; Cancel does not change the active mode. The Figma, classic and DOS presentations are mutually exclusive and use the same project.

## Architecture

`src/tui/cells.js` is a DOM-independent, bounded character-cell framebuffer with Unicode scalar glyphs, packed 4-bit foreground/background attributes, clip stacks, mnemonic handling, overlap-safe blits, detached snapshots and per-row damage. `CanvasCellRenderer` consumes only damaged spans and shares a bounded LRU glyph atlas within each presentation root. Fractional device scaling rounds absolute cell edges instead of accumulating rounded per-cell pitch. A root has an 8,388,608-pixel surface budget and a 1,048,576-pixel glyph budget; individual surfaces are also bounded. Oversized controls retain their native presentation and can recover on resize. The EGA palette is fixed to 16 colors. `src/tui/raster.js` supplies 56 independently authored, deterministic single/double/mixed line, block, shade, bullet and arrow primitives. Their integer mask fingerprint is a regression golden, not a vendor comparison. Other letterforms still use the browser monospace rasterizer. No font files, DOS binaries or vendor assets are shipped.

`src/tui/controls.js` is the replaceable paint adapter registry. `src/tui/dom.js` reads the existing materialized BrowserControl DOM into paint snapshots, composes a back buffer and diffs it into the retained front buffer. There is no second form model, layout solver, event dispatcher, binding engine or undo stack. `src/rendering/invalidation.js` provides an optional shared materialization notification used by `BrowserControl.refresh` and `BrowserForm.refresh`. This catches property-only `input.value` and selected-index changes without synthetic DOM events, polling or a shadow model. Mutation, resize, input, font and device-scale notifications coalesce at animation-frame boundaries. Own canvas mutations do not trigger repaint loops. Hidden documents suspend scheduling. Removed/adopted controls, detached presentation roots, closed documents and disabled workspaces release their observers, listeners, canvases and caches. One document-level lifetime observer is shared by its roots; stylesheet leases keep sibling hosts alive until the last renderer is disposed.

Painting is inert: canvases are aria-hidden and pointer-events:none. The original DOM remains the keyboard, pointer and accessibility target. Text, rich-text and native list/select editing expose the original editor while focused, retaining the browser caret, IME, selection, clipboard and native pickers. No synthesized key/click events or weakened iframe sandbox are required. Forced-colors and print expose the original HTML controls.

The shell uses scoped TUI chrome and text-based command/toolbox buttons on the existing docking, menu, command, property and editor infrastructure. Authored twips, geometry, auto-layout, anchors, VB6 source, control identity, application theme and history are not changed by selecting a workspace. Cell metrics affect paint resolution, not project geometry. Partial trailing cells are clipped rather than stretching the grid to fit. Collection projections account for client borders, scrolling and nonuniform ancestor scaling; clipped text remains clipped rather than shifting into view. Toolbar, calendar, data-navigation and list-view rows are read from their real child targets. Vertical sliders preserve their native increasing-upward direction. Device-pixel-ratio handling is presentation-only.

## Paint coverage

All 40 built-in toolbox controls have explicit capabilities, in addition to forms. There are 32 cell-painted adapters: Label, TextBox, CommandButton, CheckBox, OptionButton, ComboBox, ListBox, HScrollBar, VScrollBar, Timer, DriveListBox, DirListBox, FileListBox, Shape, Line, Data, TreeView, ListView, ProgressBar, Slider, StatusBar, Toolbar, RichTextBox, MSFlexGrid, MSHFlexGrid, DataGrid, DTPicker, MonthView, UpDown, ImageList, CommonDialog and Adodc.

Form/MDIForm, Frame, PictureBox, TabStrip and SSTab retain their container structure and receive scoped chrome. Image, MSChart, OLE and WebBrowser retain their native graphical/interactive surfaces. Unregistered custom/OCX controls also remain native, rather than silently losing functionality. These are explicit fallback capabilities, not assertions that every control is rendered entirely as text.

## Runtime and extension APIs

F5 and design-mode Immediate pass through the existing trusted runtime-document loader. DOS mode contributes only validated palette/cell attributes on the runtime HTML root. The normally bundled runtime mounts presentation on each ApplicationHost stage, including opaque-origin sandboxed iframes. Direct `new ApplicationHost` construction uses the same lifetime path as `mountApplication`. Sibling and nested applications can choose independent palettes or remain classic; a native host establishes an ownership boundary so an outer TUI renderer cannot adopt its controls. `host.dispose()` releases its own presenter exactly once, and a failed mount releases the host before rethrowing. Native hosts still authorize the final document URL/CSP; loader refusal never falls back to srcdoc.

```js
await vb6Studio.dosMode.configure({mode: 'dos', profile: 'commander', cellWidth: 8, cellHeight: 16});
const cells = vb6Studio.dosMode.snapshot();
await vb6Studio.dosMode.configure({mode: 'classic'});
```

Palettes are `turbo`, `commander`, `win31`, and `monochrome`. Third-party painters register through `vb6Studio.dosMode.registry.register(type, painter, {capability: 'cells'})`; registration returns an idempotent unregister function. Register before mounting that control. Paint snapshots are display data, not writable VB6 objects. `VB6Runtime.mountApplication(project, container, {presentation: {mode: 'dos', profile: 'turbo'}})` selects TUI presentation for an embedding host. An existing application can use `host.setPresentation({mode: 'dos', profile: 'win31'})` or `{mode: 'classic'}` without replacing controls. Workspace preferences are not silently written into standalone exports or project files.

## Verification and current fidelity boundary

Run `node --test tests/tui-*.test.mjs`, `npm run build`, and `python tools/dos-browser-tests.py`. The browser suite belongs to the existing `integration-authoring` CI group and runs on Chromium, Firefox and WebKit; it checks the all-control fixture, mode transitions, unchanged model/control identity, inspector/undo, cancellation, preview sandbox, VB6 button events, native editing and disposal. Runtime-only cases additionally check independent and nested applications, direct host construction, live value repaint, password snapshots, fractional cell clipping, native slider direction, unchanged geometry, idle scheduling, stylesheet ownership and detached-root cleanup. Failure reports retain the actual runtime frame states and control DOM without weakening the sandbox. Reports and screenshots are evidence of the current renderer, not vendor reference goldens. `VB6_ORIGIN=file` checks the standalone file; `VB6_ORIGIN=memory` permits offline DOM/interaction qualification without navigation or origin storage.

This implementation is not an MS-DOS/FreeDOS emulator, Windows 3.1 window manager, or binary clone of Norton Commander/Turbo Vision. The profile names describe design references. The shell is themed retained HTML, not a single hardware text-mode screen. Only the 56 geometric primitives have deterministic pixel masks; remaining glyphs use the browser's local monospace rasterizer rather than an exact IBM VGA ROM atlas. Rich/native islands remain, and active input editing uses the original editor. Native reference capture, exact glyph/cell goldens, wholly cell-rendered shell/container chrome and complete graphical-to-text projection are outstanding for the requested 100% visual-parity target. No exact native-pixel parity certification is claimed.
